# tools/

Службові скрипти. На сайт не потрапляють: `.vercelignore` пропускає тільки сторінки.

| Файл | Що це |
|---|---|
| [`timecount.py`](timecount.py) | Скільки часу пішло на проєкт — за логами сесій Claude Code і комітами git. |

---

## Час на проєкт

```bash
python3 tools/timecount.py
```

Друкує відрізки роботи з комітами, підсумок по днях і загальний час: з Claude, поза ним і разом.

**Звідки дані.** Логи всіх сесій Claude Code, відкритих у цій теці та її worktree (`~/.claude/projects/…-Way/`). Коміти git лише підписують відрізки й на час не впливають.

**Як рахує.**
- Повідомлення всіх сесій лягають на одну шкалу часу. Паралельні сесії не рахуються двічі.
- Тиша понад 30 хв — перерва. Коротші паузи — робота: після них майже завжди йде промпт, який відповідає на щойно прочитане.
- До кожного відрізка додається 5 хв — прочитати останню відповідь.
- Верхня межа — той самий підрахунок із порогом 45 хв. Чи була довша пауза роботою, з логів не видно.
- Рядок «Claude» — від промпту чи результату інструмента до наступної дії Claude, без очікування на відповідь людини. Рядок «людина» — решта.

Пороги — константи на початку скрипта.

**Чого в логах немає.** Зустрічі, Figma, читання й обдумування поза сесією. Таке вписується руками в список `OFFLINE` на початку скрипта: дата, що робили, хвилини.

**Кеш.** Claude Code стирає логи сесій, до яких не поверталися 30 днів (строк задає `cleanupPeriodDays` у `~/.claude/settings.json`). Тому скрипт зберігає витяг таймстемпів у `tools/.timecount-cache.json` — у git він не йде — і бере звідти сесії, чиїх логів уже немає. Щоб нові сесії встигли потрапити в кеш, скрипт варто запускати хоча б раз на місяць.

Формат логів Claude Code внутрішній і не задокументований. Якщо після оновлення Claude Code цифри раптом впадуть, спершу перевірити скрипт.
