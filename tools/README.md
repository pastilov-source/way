# tools/

Службові скрипти. На сайт не потрапляють: `.vercelignore` пропускає тільки сторінки.

| Файл | Що це |
|---|---|
| [`timecount.py`](timecount.py) | Скільки часу пішло на проєкт — за логами сесій Claude Code і комітами git. |
| [`build_ia.py`](build_ia.py) | Збирає сторінку `wireframes/ia.html` із `wireframes/sitemap.md` і `wireframes/flows.md`. |
| [`wf_tree.py`](wf_tree.py) | Перелік сторінок каркасів; вставляє в кожну дерево каркасів (розділи й екрани) і стани екрана зверху (основні й вкладки); друкує таблицю для `_conventions.md`. |
| [`wf_audit.py`](wf_audit.py) | Звіряє набір каркасів: навігація, нейминг, зони з sitemap, посилання, глухі кути. |
| [`wf_review.py`](wf_review.py) | Критика каркасів за п'ятьма дефектами: заглушки, відсутні стани, глухі кути, зони без дії, екрани не з карти. |

## Час на проєкт

```bash
python3 tools/timecount.py
```

Друкує відрізки роботи з комітами, підсумок по днях і загальний час: з Claude, поза ним і разом.

**Звідки дані.** Логи всіх сесій Claude Code, відкритих у цій теці та її worktree (`~/.claude/projects/…-Way/`). Коміти git лише підписують відрізки й на час не впливають.

**Як рахує.**
- Повідомлення всіх сесій лягають на одну шкалу часу. Паралельні сесії не рахуються двічі.
- Тиша понад 30 хв — перерва. Коротші паузи — робота: після них майже завжди йде промпт, який відповідає на щойно прочитане.
- До кожного відрізка додається 5 хв — прочитати останню відповідь.
- Верхня межа — той самий підрахунок із порогом 45 хв. Чи була довша пауза роботою, з логів не видно.
- Рядок «Claude» — від промпту чи результату інструмента до наступної дії Claude, без очікування на відповідь людини. Рядок «людина» — решта.

Пороги — константи на початку скрипта.

**Чого в логах немає.** Зустрічі, Figma, читання й обдумування поза сесією. Таке вписується руками в список `OFFLINE` на початку скрипта: дата, що робили, хвилини.

**Кеш.** Claude Code стирає логи сесій, до яких не поверталися 30 днів (строк задає `cleanupPeriodDays` у `~/.claude/settings.json`). Тому скрипт зберігає витяг таймстемпів у `tools/.timecount-cache.json` — у git він не йде — і бере звідти сесії, чиїх логів уже немає. Щоб нові сесії встигли потрапити в кеш, скрипт варто запускати хоча б раз на місяць.

Формат логів Claude Code внутрішній і не задокументований. Якщо після оновлення Claude Code цифри раптом впадуть, спершу перевірити скрипт.

## Сторінка структури

```bash
python3 tools/build_ia.py
```

Перезбирає `wireframes/ia.html` із `wireframes/sitemap.md` і `wireframes/flows.md`. Запускати після кожної правки цих двох файлів; саму сторінку руками не правити.

**Що бере з md.** Таблицю сутностей, дерево екранів, розділи «Навігація», «Трасування», «Рішення виконавця» й «Відкрите» зі `sitemap.md`; усі діаграми з поясненнями — з `flows.md`. Стилі — з `research/personas.html`.

**Діаграми** малює Mermaid із CDN у темній темі; кольори станів, успіхів і тупиків скрипт перефарбовує під темне тло.

## Каркаси

```bash
python3 tools/wf_tree.py
python3 tools/wf_audit.py
python3 tools/wf_review.py
```

Три скрипти тримають набір `wireframes/*.html` узгодженим. Запускати всі три після будь-якої правки каркасів; обидві перевірки мають сказати «0». Код виходу 1, якщо є проблеми.

**`wf_tree.py` — єдине джерело переліку.** Список `SECTIONS` на початку: розділ → екран → стани, для кожного — файл, назва в дереві, мітка, рівень (стан чи варіант) і flow.
- Без аргументів — вставляє в кожну сторінку дерево каркасів (лише розділи й екрани) і стани екрана зверху, до трьох рівнів: основні й «особливі стани» → варіанти вибраного основного або перелік особливих → варіанти вибраного особливого. Кожен рівень показує лише дітей вибраного вище. Сторінка отримує їх на місці `<!-- WF-TREE -->` і `<!-- WF-STATES -->` або замість наявних блоків, тож запуск повторний безпечно.
- `--list` — перелік файлів.
- `--table` — таблиця для `wireframes/_conventions.md`, розділ 4.

**Новий стан чи екран.**
1. Додати рядок у `SECTIONS`.
2. Зробити сторінку з сусіднього стану: ті самі зони, на місці дерева й перемикача — `<!-- WF-TREE -->` і `<!-- WF-STATES -->`.
3. `python3 tools/wf_tree.py` — новий стан з'явиться у вкладках на всіх сторінках свого екрана.
4. Таблицю з `--table` вставити в `_conventions.md`.
5. `wf_audit.py` і `wf_review.py`.

**`wf_audit.py` — узгодженість.**
- `head` однаковий, без JS і стилів на сторінці.
- Дерево й перемикач — точно як із `wf_tree.py`, поточний вузол позначено.
- `<title>`, один `h1`, шапка, службова смуга, «Куди далі».
- Зони — лише секції з дерева `sitemap.md`: скрипт читає їх із блоку після «### Дерево».
- Кожне посилання й `form action` веде на наявний файл; у кожного стану є вихід поза деревом.
- Назви файлів — за правилом.
- Наприкінці: сторінки без вхідних переходів і html поза переліком.

**`wf_review.py` — критика.**
- П'ять дефектів із `wireframes/_critique.md`.
- Вихід стану рахується лише з самого продукту: без службової смуги, дерева, перемикача й шапки.
- «Немає стану» — і за таблицею `_screens.md`, і за службовими рядками «— ще немає».
- Редагування на місці («Змінити», «Додати ресурс») і `ia.html` — прийняті, у дефекти не йдуть.

Стилі сторінок — у `wireframes/_wireframe.css`, правила — у `wireframes/_conventions.md`.
